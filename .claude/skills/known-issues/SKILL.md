# Known issues

Look the failure up here first. Only debug from scratch if nothing matches, then add the new cause as a row. Fixed or obsolete rows move to `docs/archive/KNOWN_ISSUES_ARCHIVE.md`. The Godot build's table (GDScript, class cache, scenes) is frozen with it in `legacy/.claude/skills/godot-known-issues/SKILL.md`.

| Symptom | Cause | Fix |
| --- | --- | --- |
| Markdown table formatting warning (`MD060`) | Table delimiter `\|---\|---\|` lacks padding spaces | Pad with spaces: `\| --- \| --- \|` |
| Markdown heading/list blanks (`MD022`, `MD032`) | Missing blank line immediately before/after `#` heading or list | Add exactly 1 blank line above and below |
| Markdown multiple blank lines (`MD012`) | Consecutive blank lines in `.md` file | Reduce to single blank line |
| `sed` line edits corrupt blocks | Line numbers shifted | Never use sed ranges; use Edit |
| A commit lands although `tools/fc.sh docs` printed `FAIL` | Piping `fc.sh docs` into `tail` before `&& git commit` takes the exit code of `tail` | Capture the output and test it, or run `fc.sh docs` on its own first |
| An append-only table (`docs/archive/TASKS_DONE.md`, HISTORY, decisions) shrinks after a merge | A conflict was resolved by taking one side | Keep both sides' rows; compare `wc -l` with the base before committing |
| (desktop) `git worktree remove` fails with "Permission denied" | OneDrive marks folders read-only and Git for Windows cannot remove them | `powershell -NoProfile -File tools/wt_remove.ps1 ../tactical-rpg-<task> claude/<task>` (also deletes its build folder, WTCLEAN1); if an entry survives, clear attributes on `.git/worktrees/<name>`, delete it, `git worktree prune` |
| (desktop) `git checkout` fails with `cannot stat 'engine': Invalid argument`; a forced checkout stops half-way ("unable to unlink 'engine'") | The checkout lived under OneDrive: its folders are cloud reparse points (tag 0x9000e01a) and Git for Windows 2.56 cannot stat one when a checkout must create files inside it (2026-10-19, SPLIT1-1) | Keep checkouts and worktrees outside OneDrive (`C:\dev\tactical-rpg`, decision "Repository outside OneDrive"); to recover a half-applied checkout, `git reset --hard HEAD` restores the working tree without creating files in such a folder |
| (desktop) A build "Blocking waiting for file lock on build directory", or a worktree's tests run another worktree's code | Every checkout shares `.cargo/config.toml`'s target folder | `tools/fc.sh` and `check_project.ps1` give a linked worktree its own folder (`<target>-<folder name>`); raw `cargo` there needs `CARGO_TARGET_DIR` set the same way |
| (desktop) `os error 4551` "An Application Control policy has blocked this file", or Git Bash "Permission denied" starting an engine exe | Windows Smart App Control blocks unsigned freshly built binaries (it was turned off on 2026-10-19; this returns if it is turned on again) | The gates delete the blocked test exe and relink (4 tries); PowerShell `Start-Process` starts a GUI build that cmd or Git Bash cannot; the lasting fix is Smart App Control off |
| (Linux, cloud, CI) `rustup` tries to install `stable-x86_64-pc-windows-gnullvm`, or builds go to a `C:/Users/...` folder | `rust-toolchain.toml` and `.cargo/config.toml` are the desktop's | Set `RUSTUP_TOOLCHAIN=stable` and `CARGO_TARGET_DIR=<checkout>/target` (the cloud hook and `gate.yml` do) |
| The gate is green locally but CI (or a fresh checkout) fails a parity test with "missing ..." | The test needs a file in `games/emberwake/parity/out` that this machine recorded earlier but CI's `export.sh` run does not write (found 2026-10-19: `trace_parity` asserted traces exist; `hash.json` was opt-in) | Parity tests skip themselves when their recording is missing; files CI must check go in `export.gd`'s default `only` list. Reproduce with a fresh clone, `games/emberwake/parity/export.sh`, then `tools/fc.sh gate` |
| A parity suite passes instantly and prints "no traces" / "run games/emberwake/parity/export.sh" | `games/emberwake/parity/out` (gitignored) is missing in this checkout | `tools/fc.sh parity` (needs Godot 4.7.2; `games/emberwake/parity/export.sh` alone covers the data, unit, damage, save and resave suites) |
| In a fresh worktree every trace diverges (`trace_parity` 120/120, `world_traces` 240/240) | Its `games/emberwake/parity/out` was copied from a stale recording: on 2026-10-25 the main checkout still held the 2026-10-19 one, while `C:/dev/tactical-rpg-dev` held the 2026-10-21/22 one | Copy `parity/out` from the newest recording (the main checkout's was replaced on 2026-10-25; the old copy sits outside the repo at `C:/dev/parity-out-stale-2026-10-19`), or re-record with `tools/fc.sh parity`; never edit traces |
| The gate prints `[layers] <file>:<line> names game "<id>"` or `path dependency into games/` | Engine or kit code, a comment, a test fixture or a manifest names a game (KIT1-G layer check) | Move the game-specific text or values into the game crate (a façade passes them in); use a neutral fixture id such as `demo` |
| `trace_parity`, `world_traces` or `journey` diverges after a change | The change altered a rule the frozen Godot build defines | Unintended: fix the engine. Intended by the approved task: retire the check it breaks (remove or narrow the suite or its recorded cases) and name it in the commit and HISTORY (CLAUDE.md "Godot parity"); never edit the traces |
| `data_source` fails after a data edit | It compares the loader on `legacy/data` with Godot's export of it, so a live `games/emberwake/data/` edit cannot break it; the loader or the schema changed | Fix the loader (`emberwake_content::source`); `kits/rpg/schema.json` must equal `parity/out/schema.json` |
| `aegis content upsert` refuses an entry with "names the unknown ..." and writes nothing | A reference (class, item, skill, unit) names no catalog entry; the writer rolls the file back | Upsert the referenced entry first (seeds list steps in dependency order: item families, items, skills, passives, classes, units, encounters) or fix the id |
| The first `aegis content` save of a file reorders its fields | The file is older than its schema (nine shipped files were); Godot's own save reorders them the same way | Expected once; review the diff, the values do not change |
| Key order changes in a JSON value after an edit in engine code | `serde_json::Map::remove` swaps the last key into the hole | Use `shift_remove` (engine docs: `aegis_core::json`) |
| A loader or writer test fails on `1` vs `1.0` | Godot's JSON.parse makes every number a float; whole floats come back as ints only where the schema or `_json_ints` says | Compare through the `aegis_core::json` helpers; keep int / float types as Godot writes them |
| (desktop) IDE shows "Could not find script for class ..." in `games/emberwake/parity/godot/*.gd` | The Godot language server analyses them against the root, which is no longer a Godot project | Stale: those scripts run inside `legacy/` (`games/emberwake/parity/*.sh` pass `--path legacy`); close any Godot editor open on the old root |
| `run.bat dev` or `run.bat opt <x>` says the folder has no engine | That branch is older than the switch (the Godot `develop`, an old option branch) | Branch it again from `main`; old Godot branches run from the `legacy` branch with its own launcher |
| A log line or text built from a float differs from Godot by one in the last printed digit ("x1.82" vs "x1.81") while every number in the trace matches | Godot's JSON reader (built-in strtod) reads some decimals one ulp off (0.7 as 0.7000000000000001), so a value on a rounding tie formats differently; Godot's `%.2f` itself rounds the exact binary value, ties away from zero | Intended (decision "Exact number parsing"): compare such text with a one-step tolerance on that number, never by changing the engine's parsing |
| A test in one worktree fails to compile against code that exists in its sources ("cannot find X in crate Y") | `.cargo/config.toml` points every worktree at one shared target folder; a build in another worktree left a stale artifact of the same crate | Touch the crate's `lib.rs` and rebuild, or give each worktree its own `CARGO_TARGET_DIR` while two are being built |
| CI `gate` fails with `failed to run custom build command for alsa-sys` (or another `*-sys` crate) while the desktop gate passes | A new native dependency (rodio -> cpal -> ALSA) needs a Linux system library the Windows desktop does not | Install it in `.github/workflows/gate.yml` (step "System libraries": `libasound2-dev pkg-config`); when adding a crate with native parts, check its Linux build needs before the release PR |
| A doc edited by a Python script shows CRLF warnings ("CRLF will be replaced by LF") or a whole-file diff | `Path.write_text` on Windows turns `\n` into CRLF; the repo keeps LF | Write with `newline="\n"` (or `open(..., "w", newline="\n")`); repair with `sed -i 's/\r$//' <file>` |
| A game started or loaded from a screen opened over another screen vanishes and the next frame panics "a game is running" | A screen's `leave()` that clears shared Cx state (the game, the debug flag) also runs on the Reset that `enter_game` queues, after the new game is in place (UIGALLERY1 review) | Clear only state you can prove is still yours (the gallery's sample game carries `Game::sample`) |
| A commit meant for one layer also holds files of another (for example the engine commit 17cc42c carries the 285 asset moves of ASSETORG2-G) | `git mv` stages its renames at once, and `git add <paths> && git commit` commits the whole index, not just the paths added | After `git mv`, commit with explicit pathspecs (`git commit -m ... -- <paths of this layer>`, both sides of each rename), or `git mv` only right before the commit that should hold the moves; check `git diff --cached --stat` before each commit |
| `aegis_ui` test `shell::tests::a_click_comes_before_what_it_opens` fails once on the trail-types assert (`["click", "button", "modal"]`) and passes on rerun | Seen while another build or test loaded the machine (2026-10-22); suspected a timing-dependent trail event (a hover past `HOVER_MS`) or the shared playtest test queues | Rerun it; if it fails again, make the test independent of timing (no wall-clock hover in the trail). 2026-10-25: it also failed with an extra `asset` trail event (body `rogue`, `missing_file`) after `modal`, which points to a shared trail/event queue fed by a parallel test rather than hover timing. |
| A docs commit lands although `tools/fc.sh docs` failed (2026-10-22, a47519c fixed it) | `bash tools/fc.sh docs 2>&1 \| tail -1 && git commit ...`: the pipeline's status is `tail`'s, always 0, so the `&&` chain goes on after a FAIL | Capture the output and test for the clean line: `bash tools/fc.sh docs > out.txt 2>&1; grep -q "markdown lint clean" out.txt && git commit ...` (or `set -o pipefail`) |
| `tools/patch_notes.py` lists only some of the commits since the marker (2026-10-23: the SPRITE1, PLAYUI1 and PROPS1 landings were missing) | It walks the first-parent line of `develop`; work merged from a task branch (a merge commit) hides the branch's own commits | List them with `git log --no-merges --format='%ad %h %s' --date=short <marker>..HEAD` and write the sections from that; fix the script to use `--no-merges` |
| The gate fails parity tests with "missing ...parity/out..." in a worktree whose `parity/out` is present, and plain `cargo test` passes (2026-10-23) | A scratch copy built into this worktree's gate target folder (`<target-dir>-<worktree>`, check_project.ps1) left test binaries whose `CARGO_MANIFEST_DIR` points at the scratch copy, since deleted | `cargo clean -p emberwake_rules -p emberwake_battle -p emberwake_host` with `CARGO_TARGET_DIR` set to that folder, then rerun the gate; give scratch copies their own `CARGO_TARGET_DIR` |
| A commit carries conflict markers (`<<<<<<< Updated upstream`) although the chain looked fine (2026-10-23, 7ba00b7, fixed in 03aa7e6) | `git stash; git merge; git stash pop` hit a conflict, `stash pop` left the file unmerged, and the `;`/`&&` chain went on to `git commit -- <paths>` | Commit before syncing (or merge without stashing), and check for markers before every commit: `git diff --cached \| grep -n '^+<<<<<<<'` must find nothing |
