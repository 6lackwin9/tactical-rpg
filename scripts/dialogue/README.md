# scripts/dialogue

System: S11 (spec `docs/specs/DLG1_L.md`, rules `docs/specs/S11_RULES.md`). Status: in progress (commit 1 schema, commit 2 runtime; commit 3 panels next).

Purpose: dialogue trees, quest services, NPC presence, shops and gold.

## Files

- `dialogue_rules.gd` (`DialogueRules`): constants (`MAX_NODES`, `MAX_CHOICES`, node / choice keys, `CONDITION_KINDS`, `QUEST_STATUSES`, `EFFECTS`, `NODE_EFFECTS`, json ref keys, `SERVICE_IDS`, `DEFAULT_LINES`, `TOKENS`, `TEXT_TOKENS`) and pure validation: `tree_errors(world_id, e)` (WorldCatalog kind `dialogues`; authored node / choice texts allow only `{npc}` and `{gold}`), `tree_warnings(e)` / `dialogue_warnings(world_id)` (unreachable nodes; a `give` node on a dialogue cycle unless every way in is a choice guarded by `unless` + a matching `set_flag`), `conditions_errors`, `effects_errors` (choice order rules: `turn_in` first, `open_shop` / `fight` last), `line_errors` / `service_lines_errors`, the gone-NPC lint `quest_warnings(world_id)`; runtime reads `is_gone`, `condition_holds`, `choice_open`, `best_stat` (best ACTIVE member, gear and passives included), `stat_prefix`, `start_gold`, `service_line`, `fill`, `complete_from_journal`.
- `dialogue_runner.gd` (`DialogueRunner`): one conversation, never saved. `open(gs, character_ref)` (`errors` non-empty = refused, e.g. "Mara is gone."), `view()` ({speaker, speaker_name, node, text, choices [{text, locked}], end, next, shop, pending}), `choose(index)` (pre-checks every effect, all-or-nothing; returns `pending`, `shop`, `fight`, `node` or `end`), `confirm_turn_in(recipient_id, picks)` / `cancel()`, `close_shop()` (back to the opening node without re-running its effects; user 2026-10-17), `advance()` (for `next` and end nodes), static `after_fight(gs, fight, outcome)` (BattleBridge.apply, plus ExploreRunner.wake on lost).
- `shop_rules.gd` (`ShopRules`): `shop_errors(world_id, e)` for kind `shops`; `buy_types()` (every ItemFamilies type but QUEST, the `buys` default); runtime `is_open`, integer `buy_price` / `sell_price`, `offers`, `buy`, `sell_list`, `sell`.
- `rep_rules.gd` (`RepRules`, REP1-L, spec `docs/specs/REP1_L.md`): reputation is the int flag `rep.<faction qid, ":" as ".">` in `MIN`..`MAX` (-100..100) in the flat flag registry (no own GameState key, no save bump). `key`, `faction_qid_of`, `value_error` (the rep value rule), `key_resolves` / `key_warnings(world_id)` (a rep key naming no faction of the world is a warning, also in `WorldCatalog.world_warnings`), `BANDS` (hostile <= -50, unfriendly -49..-10, neutral -9..9, friendly 10..49, honoured >= 50), `band`, `buy_pct` / `sell_pct` (115/85, 100/100, 95/105, 90/110), `standing(gs, faction_ref)` (0 when missing), `standing_text`. No ripple through faction `relations`.
- `service_catalog.gd` (`ServiceCatalog`): the base service lines in `data/dialogue/services.json`, same contract as `QuestCatalog` (`upsert`, `remove`, `save`, `use_path`, `validate_all`, `warnings_all` for missing ids, `text_of` with the `DEFAULT_LINES` fallback).

## Rules

- Content goes through `WorldCatalog.upsert` (trees, shops, characters, manifest via `update_manifest`) and `ServiceCatalog.upsert`, never raw JSON.
- Dialogue conditions (`flag`, `quest`, `items`, `gold`, `stat`) exist on dialogue choices only; markers, quests, loot, routes and `gone_flags` keep the M4 flag-only grammar. Every flag condition takes the optional `op` (`==` default, `!=`, `>=`, `<=`, `>`, `<`; see `scripts/quests/README.md`).
- `add_flag {key, delta, min, max}` (node or choice effect, REP1-L): current (missing = 0) + delta, clamped to `min` / `max` when given and to -100..100 for `rep.` keys; a non-int flag refuses the whole choice ("Flag '%s' is not a number."); on a node it is skipped.
- Reputation display: `view()` carries `faction`, `faction_name` and `band` of the character talked to; a choice whose `requires` holds a `rep.` condition with an ordering op gets the generated prefix `[<Faction name> <band of the bound>] ` (`DialogueRules.rep_prefix`, before the stat prefix). The dialogue and shop debug panels show "Faction: band".
- Supplies (TRAV2-L): a shop with `supply_price` > 0 appends the offer `{kind: "supplies", id: "supplies", item: "", count: 1, price: supply_price, left: room up to 99}` after the loot rows (fixed price: no `buy_mult`, no band factor; unlimited; not in `gs.shops`). `buy(gs, shop, "supplies", "supplies", n)`: more than the room refuses ("You can carry at most 99 supplies."), then gold; all-or-nothing; returns `supplies` instead of `items`. The shop panel shows "Gold: G  Supplies: S/99" and Supplies x1 / x5 buttons.
- Shops (REP1-L): the buy / sell factors of the keeper faction's band replace DLG1's 100 in the same integer formulas (`keeper_faction`, `keeper_band`; a keeper without a faction is neutral); fixed stock and loot prices ignore them; a hostile keeper's shop is closed (no offers, buying, selling or service choice).
- Services are generated on the start node (unless `services: false`) after the authored choices: offers (resolved giver = the character, `available`; Accept and Decline both return to the start node), turn-ins (effective turn-in = the character, `ready`), open shops it keeps, Farewell. They may push the start node past `MAX_CHOICES` (allowed: the cap is an authoring limit).
- `start_quest` is refused unless the resolved giver is "" or the character talked to; `turn_in` likewise for the effective turn-in. `QuestRunner.start` / `complete` stay unrestricted for tests and tools.
- A gone character (any `gone_flags` holds) cannot be opened, its npc markers are absent (`ExploreRunner.presence`), its shops are closed.
- Party gold (`PartyState.gold`, 0..`GOLD_MAX`, additions capped) comes from quest `rewards.gold`, chest `gold`, selling and dialogue `give`; `NewGame` starts at the resolved `start_gold`.
- Tests: `scripts/tests/dialogue_test_suite.gd` (sandbox content fork, quest / service / map files, save folder and world root); `scripts/tests/reputation_test_suite.gd` (REP1-L: operators, rep values, add_flag, quest reputation, bands, prices, hostile shops, saves, panels).
