# scripts/ui/menus

System: S7, S13. Status: UI1-L built (main menu, new game, save / load slots, settings, hub); UI2-L built (party, level-up, skills loadout, gear, battle results); UI3-L built (quest journal).

Every screen is a headless `RefCounted` model plus a thin view (spec `docs/specs/UI1_L.md`):

| Screen id | Model | View |
| --- | --- | --- |
| (stack) | `menu_router.gd` (`MenuRouter`: push / pop / replace / clear_to, `ask` + `confirm` / `decline`, signals `changed`, `confirm_needed`, `notice`, `game_started`, `quit_requested`) | `main_menu_view.gd` (`MainMenuView`, host of `scenes/main_menu.tscn`: renders the top screen, the question overlay, the game scene) |
| `main` | `main_menu_model.gd` | `main_screen_view.gd` |
| `new_game` | `new_game_model.gd` | `new_game_view.gd` |
| `load`, `save` | `save_slots_model.gd` | `save_slots_view.gd` (rows in a `SlotScroll` ScrollContainer; `BackButton` fixed below it) |
| `settings` | `settings_model.gd` (level lists and names for the two stepped keys; DISPLAY1 choice lists, the Keep / Revert countdown state) | `settings_view.gd` (a `SettingsTabs` `TabContainer` (Sound / Display / Gameplay / Controls (CONTROLS-HELP: read-only key list built from `controls_list.gd`), each a scrolling label / control / value grid; `SettingsModel.tab` keeps the tab across re-renders); volumes are sliders, animation speed and text size are four-notch `HSlider`s (text size previews live, no sample label), the Skip animations `CheckBox` sits on the speed row, the display choices are `OptionButton`s, vsync is a `CheckBox`, an "In use" row shows the real window mode and size, and a close cross (`SettingsClose`, header, same path as Esc) replaces Back; Apply and a flat Restore defaults sit in a `SettingsFooter` at the bottom right below the scroll; the view lives in the host's `SettingsPanel` over a dimmed `PopupBackdrop` (`MainMenuView._build_popup`; `render()` draws the screen below, with focus off, behind it); a window mode / size applies on select and opens the Keep / Revert countdown (`SettingsModel.start_display_change`); right click is Back on every screen (`MainMenuView._input`, before the GUI); web shows only a Fullscreen checkbox) |
| (display) | - | `display_settings.gd` (`DisplaySettings`: window mode, size, vsync and frame cap through a `Backend`; the base `Backend` only records calls and is used headless and in tests, `RealBackend` calls `DisplayServer` / `Engine`; `apply_saved()` at boot) |
| (style) | - | `menu_style.gd` (`MenuStyle.theme()`: bordered Button states and a visible CheckBox, set on the menu column and the question overlay only, never on combat UI; UIR-1: `MenuStyle.selected_box()` / `mark_selected(button, on)` / `is_selected(button)`: a filled box with a gold edge marks the selected row, the label never changes) |
| (frame) | - | `screen_frame.gd` (UIR-1, `ScreenFrame.make(title, back, primary, extras)`: centred title, a scrolling `FrameColumn` of at most 1000 px, an `ActionBar` pinned below the scroll with Back first and the primary action last on the right; screens adopt it in UIR-2/3/4/6; `tools/frame_shot.gd` renders a sample, `xvfb-run godot -s tools/frame_shot.gd -- --scale=1.0 --out=<png>`) |
| `play` | - (UIR-2: the game scene; the bottom of the stack during play; Esc / ☰ Menu pushes `hub`) | - |
| `hub` | `hub_model.gd` (UIR-2: the game menu, a popup over the paused map; the journal, without a ScreenFrame, scrolls in it via `UNFRAMED_POPUP`) | `hub_view.gd` |
| `party` | `party_model.gd` (UIR-3: the Character popup's model: selected member, open tab, the per-tab draft models, one "Discard your changes?" rule on a tab or member switch; + `stats_model.gd`, `party_preview.gd`); args `{member, tab}` | `character_view.gd` (`CharacterView`: ScreenFrame with an X in the header, a member strip (Q / E switch), the tabs Stats / Level up / Skills / Gear, the tab body, a fixed `DetailPane` for the focused item and the action bar with the primary Confirm; the static helpers `frame()`, `new_detail()`, `show_on_focus()`, `derived_grid()` are shared) |
| `level_up` | `level_up_model.gd` | `level_up_view.gd` (`parts()` = the Level up tab: Stat / Now / Added / New rows with - / +, Auto and Revert beside them, Confirm primary; `build()` shows it alone for the battle results) |
| `loadout` | `loadout_model.gd` (rows also carry `active_tier`, `description`, `next_unlock`) | `loadout_view.gd` (`parts()` = the Skills tab: chips, one row per family with only its active rank and description) |
| `gear` | `gear_model.gd` (+ `party_gear_bridge.gd` for `CharacterEquipmentModal`) | `gear_view.gd` (`parts()` = the Gear tab: slots, stash, battle pouch; Gear board and Reset in the bar) |
| `results` | `battle_results_model.gd` | `battle_results_view.gd` |
| `journal` | `journal_model.gd` (read only over `QuestRunner`) | `journal_view.gd` |

Rules: models call only rule APIs (`NewGame`, `SaveGame`, `WorldCatalog`, `CurrentGame`, `SettingsFile`) and never touch a Node; actions return `Array[String]` problems (empty = done); a new screen adds a `MenuRouter` id, a `make_model` case and a view case in `MainMenuView.render`. Party screens take `{member}` (results take `{award, advanced, outcome}`; outcome won / lost / fled sets the headline, BATTLE1-L) through `push(id, args)`; popping a screen calls `refresh()` on the one below when it has it. Tests: `scripts/tests/menus_test_suite.gd`, `scripts/tests/settings_ui_test_suite.gd` (levels, snapping, screens fit 1280x720 at every text size / speed, popup panel, close cross, backdrop), `scripts/tests/display_test_suite.gd` (display keys, backend calls, size fitting, Keep / Revert / timeout, web rows, layout at 1280x720, 1280x800 and 1680x720), `scripts/tests/party_screen_test_suite.gd`, `scripts/tests/save_io_test_suite.gd`, `scripts/tests/journal_test_suite.gd`. A view may set the `MainMenuView.FOCUS_META` meta to the control the host focuses first.
