# Decisions: combat

Settled; do not re-litigate without asking the user. Scope: S1 combat core, S12 combat extensions, statuses, riposte, stances, S4 AI. Rows moved unchanged from `docs/DECISIONS.md` on 2026-10-17 (CLN-10), in their original order; append new rows at the end of the table. Index and global rules: `docs/DECISIONS.md`; superseded rows: `docs/decisions/archive.md`.

| Decision | Choice | Why |
| --- | --- | --- |
| Combat extensions (S12) | Additive: influence stat inputs to the formula or wrap the base damage formula; `DamageCalculator` core stays the single formula, S1 keeps `balance-ready` | User 2026-10-15: advanced options isolated from the formula |
| Bleed | 6% of max HP at round end (min 1), ignores armor and guard, can defeat; statuses queued this round start next round and last `status_rounds` | M1 builder default 2026-10-15 (rate open for tuning at the balance pass) |
| Gap-close | `dash_tiles` on attack skills: dash is the unit's move for the round, must come first, AP = skill level, refused if target already in reach | M1 2026-10-15 |
| Support skills | Heal = `heal_base + round(KNOW or INT x heal_mult)` via `SupportRules`, never through `DamageCalculator`; `learned_only` skills reach a unit only via extra_skills / learn_skill / class path | M1 2026-10-15 |
| Tuning notes from M1 | Bleed 6% max HP stays until the balance report; support reach may drop from 0-3 to 0-2 if range 3 is too strong; heals per round (now 2) may become 1 per party member or an AP penalty for repeat heals; gap-close skills need target distance >= 2 (already true: refused when in reach; diagonals count as distance 2) | User 2026-10-15, to review after the balance pass |
| Riposte (warrior reactive damage) | A base defensive self-buff skill: mitigation lower than Guard, grants the `riposte` status for 2 rounds; removed when the unit changes stance (moving keeps stance); counters adjacent melee attackers for 50% attack power, once per attacker per round. Other skill types usually force a stance change, which discourages mixing | User 2026-10-15 |
| Riposte implementation (M2a) | Active from the block the skill starts (self-buff granted immediately, unlike queued debuffs); "2 rounds" counts the cast round; counter = `DamageCalculator.compute` at skill_mult 0.5 so stance matchup applies (a Defensive warrior vs an Offensive attacker counters ~62%); once per attacker per round; ended by any stance change; snapshots now store statuses so undo rewinds them | M2a 2026-10-15, flagged for balance review |
| cleanse | Approved engine effect: removes statuses from an ally (M2c-2 engine slice) | User 2026-10-15 |
| M2c-2a2 engine pieces (2026-10-15) | CLEANSE: `cleanse_statuses` (stagger/stun/root/bleed or `all`), debuffs only (never buffs/riposte), active + pending, runs before heal/grant so one skill can heal+cleanse+buff. DISENGAGE: own Kind, `jump_tiles`; the unit's move for the round (first in sequence), AP = skill level, rooted refused, leaps units but not walls, never onto exits, auto-picks the tile farthest from the nearest foe (or from a chosen foe / a clicked tile); fails gracefully at execution if the landing is taken. SWEEP: L-shape (sx,0),(sx,sy),(0,sy) aimed at a diagonal neighbour, hits allies. GearBudget UNARMED_VALUE = 14 when main_hand is empty and the class has other gear. Known gaps: AI never uses disengage/sweep/cleanse-only skills; "once per round" disengage not enforced (same as MOVE) | M2c-2a2 review |
| Status registry (user 2026-10-15) | Catalog all valid buffs and debuffs in one registry with stacking rules (extend duration vs increase potency vs refresh/none), resistability, caps; weaken is capped 25% non-stacking by default; build modularly | User 2026-10-15 |
| B1 Rest and stance (2026-10-16) | Rest enters Tactical (it is a tactical action) and stays free to enter; a stance change costs the single constant `CombatTypes.STANCE_SWITCH_COST` (1); Rest then Focus has no switch, Rest then an attack/Defend pays +1; no per-skill override yet; stance matrix unchanged (a resting unit is Tactical: loses to Offensive, beats Defensive) | B1 builder report |
| D1-L weaken (2026-10-16) | weaken is a debuff (resistable, cap 25, refresh_max_duration): the afflicted unit's outgoing skill power is x(1 - magnitude/100) via SkillDef.power_for and the riposte counter; magnitude is the skill field `status_magnitude` (weaken needs 1-25, other statuses 0), stored per unit in `status_magnitudes` / `pending_status_magnitudes` through the registry's potency channel (max wins); a zero-power ATTACK needs a status, is never a damaging hit (no compute, no riposte), and cannot be an area attack until area commands apply statuses (M2C2B-L X1); riposte AP/mitigation/rounds are all skill data (RiposteRules.COUNTER_MULT 0.5 is the only constant); both riposte tier models are tested in memory | D1-L review |
| M2C2B-L X1/X2 (2026-10-16) | Area attacks roll the skill's status once per unit hit (allies included, resistance applies, same log style); a DEFEND skill may grant riposte (active at once) or a support buff such as taunt/haste (queued for next round); validation allows defend- or support-grant buffs; a zero-damage area attack stays rejected (D1 rule kept) until a spec asks for it; `weapon_types`/`min_proficiency` stay ATTACK-only so shield_wall has no shield gating | M2C2B-L review |
| AI1 (2026-10-16) | `AiProfile.smart_skills` (default true; false restores the pre-AI1 behaviour, A/B it in BAL1) and `area_min_foes` (default 2, clamped 1..6). The AI uses disengage (first action, never when reckless or rooted), area attacks only when foes hit >= area_min_foes and no ally is hit, cleanse-only skills (once per round), taunt, ally buffs and debuff attacks (kept only if a strike still fits), riposte (a round-ending finisher after one strike when healthy with a melee foe adjacent; a guard alternative when low). Zero-power attacks are never the strike. Optional casts respect prefer_level. Known weak spot: cleanse casts do not verify that a needed move-then-strike still fits (same as the old heal path). Riposte finisher costs a strike for units that own riposte: revisit at BAL1. Riposte undo test now uses the aggressive preset; the balanced-preset riposte carry-over is covered in ai_skills_test_suite | AI1 review |
| S12 baseline answers (user 2026-10-17) | All recommendations in docs/specs/S12_RULES.md accepted: skill upgrades covered by SKILL1 ranks/grades + potency/unlock passives + item effects (no new upgrade system now; a limited source-granted `skill_mod` later when M4 loot needs variety); first status slice = slow, expose, fortify, regen + poison (stacking) and burn; terrain as a catalog kind `terrain` holding numbers only (zone maps stay in code until S9 map data); cover = target tile + one directional neighbour; static terrain only now (skill-left terrain later); combos = flow moves (`ends_in_stance`), stance-break disrupt and exploit (bonus vs a status). Slices S12S -> S12T -> S12C in sequence after ITEM1-L and CLASS1-L | User 2026-10-17 |
| PLAN1 (planner 2026-10-17, bug fix) | Preset plans are always confirmable: approach tiles are claims (fixed once planned, avoided by later drafts, support approaches included); speed ties keep planning order; the party preset redrafts invalid allies (one pass per ally); enemy packs share the claims; the sim prints `PLAN FAIL <unit> <reason>` and a `plan checks` total instead of silently ending the fight. Enemy approach tiles may differ from pre-PLAN1 sim runs | Planner 2026-10-17 |
| S12S-L readings (planner 2026-10-17) | Where S12S_L.md is silent: a magnitude of 0 on a status with a range is stored as the range minimum (`StatusEffects.magnitude_or_min`, in queue and grant_now; shipped data never hits it, the validator rejects 0); round-end log lines and return values keep the raw step amount, step rows record HP actually lost; AI slow picks foes nearest the caster that can reach the lowest-max-HP friend (caster included) within move plus basic-attack reach; fortify ranks friends by adjacent foes with no minimum; regen may go to a patient healed in the same round | Spec gaps found while building commits 2-3; engineering readings, revisit if play shows otherwise |
| GRID12 combat grid layout (user 2026-10-17) | The combat grid is 12 wide x 9 tall (a square grid is not required). Standard encounters deploy the party on the left and enemies on the right: melee in the front column (party x 5, enemies x 7), ranged in the back column (x 4 / x 8), rows filled from row 4 outward; overflow and reinforcement waves take the free tile nearest the arena middle on their own half. The front-to-front and back-to-front gaps (2 and 3 tiles) match the old 9x9 centre ring. No centre tile is marked; its ring icon becomes the region-map point-of-interest marker (asset key `overlay_poi`). The two side panels shrink from 340 to 270 px. Tie-breaks that prefer central tiles measure to the true middle (between columns 5 and 6 on row 4). Encounter exits on the old east edge (8, 4) move to the new east edge (11, 4); zones are widened by repeating columns 1, 4 and 7 | User 2026-10-17 (project chat); exit placement and spawn gaps chosen by the GRID12 thread to keep balance unchanged |
