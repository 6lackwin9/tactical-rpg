# Decisions: items and gear

Settled; do not re-litigate without asking the user. Scope: items, weapon hands, off-hand types, item effects, gear budget. Rows moved unchanged from `docs/DECISIONS.md` on 2026-10-17 (CLN-10), in their original order; append new rows at the end of the table. Index and global rules: `docs/DECISIONS.md`; superseded rows: `docs/decisions/archive.md`.

| Gear budget | Option A: class default loadouts validated against a budget in `ContentCatalog` (warning level); fill gaps with items. Special items may break it with a documented trade-off | User 2026-10-15 |
| Gear budget formula | One weighted number per item (weapon power, mitigation, burden penalty, ...) summed over a class's default loadout; compared with a target budget; warning level; `special` items may exceed with a documented trade-off | User 2026-10-15 (weights/target chosen in M2d and tuned at balance) |
| Gear budget constants (M2d) | Item value = power x1.0 + mitigation x1.5 + stat points x2.0 - burden x2.0 - (block cost-1) x3.0; loadout = main/off/head/body/accessories (pouch ignored); target 23 (median of the old six), band +-20% (18.4-27.6); warnings are soft and separate from `validate_all()`; a `special` item with a note excuses an over-band loadout only (never under-band); special without a note warns. Current: warrior 35 (over, to be fixed by the M2b/M2c tank kit), others in band | M2d 2026-10-15 |
| M2b items (2026-10-15) | New gear is NOT in the starter stash (keeps stash/carry/dojo numbers stable); cloth gear gated by the cloth proficiency; weapons cannot scale from KNOW (schema: STR/DEX/INT), stat bonuses cannot be negative, so drawbacks are expressed through burden, block cost and requirements; `wpn_glass_wand` is the first `special` item | M2b builder report |
| Weapon hands (user 2026-10-15) | Every weapon is main 1H, main 2H or off-hand; orb and tome are off-hand only; with a 2H main weapon the off-hand attack scales from unarmed; priest has no shield proficiency (paladin territory) | User 2026-10-15 |
| C1-L (2026-10-16) | Orb and tome are off-hand only and never two-handed; a 2H main weapon cannot be paired with them (Dojo equip path refuses; equipping a 2H main stows a held focus; catalog class/unit loadouts already refuse any off-hand with a 2H main; direct Inventory.equip and world named-item gear are not guarded - shipped data is safe, accepted gap). Items carry `effects` (passive grammar, item types: skill_potency by family or group spell/heal, status_potency 1..25, spell_reach 1..2 with a gear clamp of 1, resist); gear effects are rebuilt on every sync_from_stats_and_gear in fields separate from passive bonuses. Gear weights: skill_potency x20 per 1.0, status_potency x0.2 per point, spell_reach x3 per tile. Any code calling Inventory.equip must call sync_from_stats_and_gear afterwards | C1-L review |
| C1-A1 assets (2026-10-16) | arcane_bolt and hex gate on staff or wand only; Priest: tome 3, orb 2, no shield; wpn_tome is an off-hand tome (INT scaling, KNOW 11, +1 KNOW); asset seeds live in data/seeds/ and are idempotent so they can be re-run after a rebase | C1-A1 |
| FORGE1 item answers (user 2026-10-16) | Family hands/new rows as proposed (mace and wand 1H only, hammer 2H only, staff also 1H, crossbow copying bow, material/quest placeholders); items INHERIT from the family template with deltas; dual wield keeps its code path but a GUARD (flag, default blocking) prevents dual wielding until the system is fleshed out; band violations are soft warnings until after the balance pass, then reconsider hard enforcement with proper scoring; build the extra tier features now (iterate after the balance pass) and description tokens | User 2026-10-16 |
| Strict hand typing and no class skill loadout (user 2026-10-16) | (1) Every weapon has exactly one hand type (`main_1h`, `main_2h`, `off`); main types fit MAIN_HAND only, `off` fits OFF_HAND only, so power is budgeted per hand (family `base` and `bands` per hand, off-hand weapons lower power and higher bonus value); the dual-wield flag stays a code constant and only gates `main_1h` into OFF_HAND; worn items are kept. Skills pick a hand with enum `weapon_hand` = `main` / `off` / `both` (replaces bool `offhand`; `both` is an engine-lane follow-up, two hits via the existing paths). (2) The class carries only the unlockable skill path; the 5+3 active skill loadout is set on the UNIT (`loadout` field), default derived by the (level, order) rule; the class gear loadout is unchanged. Also accepted: Forge cannot create basic skills, Promote-to-system is not undoable, `evolves_from` base non-advanced, `advanced` is a key field, gear slots and pouch locked on system classes, standard path levels [1,3,4,5,7], missing level-1 path skill is a warning | User 2026-10-16 |
| FORGE1 round 5 answers (user 2026-10-16) | Sword main_1h base 14 (broadsword +4) accepted; a 2H main leaves the off hand empty under the strict rules (claymore-backup preset and Dojo-21 run only under the dojo legacy flag); strict hand typing is the only off-hand rule enforced now - no off-hand attack skill (shield bash etc.) is added; a future system may use the off hand to deal damage | User 2026-10-16 |
