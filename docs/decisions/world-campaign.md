# Decisions: world and campaign

Settled; do not re-litigate without asking the user. Scope: S6 worlds, S8-S11 placeholder systems (exploration, travel, dialogue), campaign scope. Rows moved unchanged from `docs/DECISIONS.md` on 2026-10-17 (CLN-10), in their original order; append new rows at the end of the table. Index and global rules: `docs/DECISIONS.md`; superseded rows: `docs/decisions/archive.md`.

| Exploration encounters | Step counter for regular mobs, rare elite chance; elites, bosses and scripted fights are placed/roaming | User 2026-10-15 |
| Playable scope | One small campaign first; more campaigns later; unify stories across worlds after several exist; UGC story mode is a later engine goal | User 2026-10-15 |
| Travel supplies | Reduced implementation only (single counter, no fail state), later slice | User 2026-10-15 |
| M4 quest answers (user 2026-10-17) | All 8 M4 recommendations accepted (templates + world binding, one flat flag registry per save, rewards xp to all active / items to stash / passive or skill to a chosen recipient, soft reward budget caps, explicit game-loop objective calls, ready + turn-in completion, save v2 with migration, separate QuestCatalog). Clarification: no connections or branching INSIDE a quest; all linkage, relations and world progress are tracked through the flag system (baseline). Quests also carry METADATA that links quests together (e.g. chains, follow-ups, related NPCs/locations) and that can be ALTERED BY FLAGS: e.g. if an NPC dies (flag) that NPC is no longer available for the quest, so the quest changes as a consequence (different giver/turn-in, objective target or reward, or the quest becomes unavailable) | User 2026-10-17 |
| M4 variant answers + world loot rewards (user 2026-10-17) | V1-V5 as recommended (ordered merge of variants; blocked/unavailable states with fields re-read on every read; `rewards_from` template references; giver/turn-in metadata only until S11; no character-level "gone" field yet). Rewards: special/unique rewards come from a shared WORLD LOOT TABLE, not quest-specific reward lists; a quest maps a pool of loot-table entries and may offer a CHOICE between them; once a loot-table reward is claimed it is removed from every other quest pool. Quests always keep generic rewards so the reward budget is met even when the special reward is gone (completing still gives the generic rewards). A common loot table lets players target rewards and pick the quests that offer what they want | User 2026-10-17 |
| M4 loot picks (user 2026-10-17) | L1 as recommended: at turn-in the player may take 0 up to `loot_picks` special rewards; untaken loot entries stay in other quests' pools and the generic rewards are granted either way (more player control) | User 2026-10-17 |
| S9-S11 baseline answers (user 2026-10-17) | All recommendations in docs/specs/S9_RULES.md, S10_RULES.md and S11_RULES.md accepted: S9 base map templates + world bindings, step-counter encounters (threshold 12..20, 10% elite), defeat = wake at spawn or last safe location fully healed, fixed patrols for roaming elites/bosses, authored (non-scaling) mob levels, save anywhere outside battle/dialogue + autosave on location entry; S10 nodes = route endpoints, fog (visited or one open route away), auto-path multi-leg trips pausing at fights, repeat road chance `repeat_pct` (default half), integer world clock advanced by travel, supplies later (at 0: road chance x1.5, no fail); S11 world kind `dialogues` + base service templates with generated service choices, strict giver/turn-in through the resolved quest + gone-NPC lint, character `gone_flags`, gold in PartyState from quests/chests/selling (no kill gold yet; adds quest reward key `gold`), reputation as int flags with comparison operators, deterministic stat checks (best active member vs threshold), no reputation spill-over. EXP1, DLG1, TRAV1 run in sequence with one save-version bump each | User 2026-10-17 |
| EXP1/REP1 spec answers (user 2026-10-17) | X1: a battle that hits its round limit with both sides standing counts as `fled` (the only escape signal CombatSession has). R1: quest variants cannot override `reputation` in REP1 | User 2026-10-17 |

(2) A whole party leaving a battle through the exit tiles counts as `fled` (no defeat penalty); only every member down is `lost`. (3) Renaming or removing a region-map template that locations use is refused until the locations are re-pointed (`MapCatalog.used_by`) | User 2026-10-17 |
| Quest fight markers (user via front desk 2026-10-17) | Option A: a quest fight marker (e.g. the courtyard warband) is hidden once it is won while its quest is active (its own done flag OR the quest completion flag); a win before the quest starts still does not count (M4), so the fight stays available then. Applies to the EXP1-A warband and the Cinder Gate ambush markers | User 2026-10-17 |
| Quest ready flag (user via front desk 2026-10-17) | Mechanism for the quest fight marker rule: `QuestRunner` sets flag `quest.<qid>.ready` when all of a quest's objectives are done (it stays set through turn-in); the Ashlands warband and ambush markers hide on it as well as on the quest completion flag. Logic task QUEST2, then an EXP1-A data update | User 2026-10-17 |
| Quest ready flag details (planner 2026-10-17, QUEST2) | Key `QuestRunner.ready_flag(qid)` = `quest.<qid with : as .>.ready`; set by `refresh()` on the active to ready step; kept through turn-in and through blocked/unblocked variant flips; cleared by `abandon()` because abandoning resets the quest. For an auto-started quest (hold_the_courtyard) "won before the quest is active" reads as "won before its objective is current" | Planner 2026-10-17 |
| DLG1 build choices (planner 2026-10-17) | Node, choice, stock and loot key sets are allowed sets with defaults (unknown keys are errors); the gone-NPC lint checks the turn-in separately only when `turn_in` is set. Commit 2: authored node and choice texts are token-checked too, allowing only `{npc}` and `{gold}` there; generated service choices may push the start node past 6 choices; a `give` effect on a node that sits on a dialogue cycle gets a lint warning (gold farm guard). DLG1-A data merges only after commit 2, so authored gold is never silently dropped | Planner 2026-10-17 |
| DLG1 runtime choices (planner 2026-10-17) | Accept and Decline both return to the start node; the turn-in service returns there after confirm; the give-on-cycle lint stays quiet when every way in is guarded by `unless` + `set_flag` (repeat-once gifts); `advance()` moves on from `next` and end nodes; gold additions clamp at `PartyState.GOLD_MAX` (RewardGrant notes the dropped amount); RewardGrant checks gold only against 0..GOLD_MAX (per-source caps stay in validation); presence lives in `ExploreRunner.presence`. Open for the user: gold beyond the cap is dropped; re-showing a node after closing a shop re-runs its node effects | Planner 2026-10-17 |
