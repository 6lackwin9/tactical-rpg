### FB-153: skill content check silently skips template validation when a family head fails to fold

- **Spec**: found in the PR4-2 phase B review (`kits/rpg/crates/rpgkit_content/src/check/skill.rs:665`)
- **Kind**: suggestion
- **Status**: open
- **Finding**: `entry_errors` runs `validate_template` only `if let Ok(folded) = fold(...)`; a fold error is dropped, so a skill whose rank rows cannot fold gets no template errors and no fold error either. The PR4-2 re-freeze exposed it: the slim `checks_golden` fixture bases lacked the loader-computed `spell_source`, every family head failed to fold, and the golden silently lost its `{jump}` token errors; on develop `shield_wall` and `mend` were already skipped (`guard_rounds` / `position` fold mismatches). The harness was aligned in PR4-2 and all 16 templated skill bases fold again. Shipped data is unaffected (the loader marks every row), but a hand-authored or seed row with a stray rank key would pass checks it should fail.
- **Recommendation**: **Option A (recommended)**: report the fold error as a content error on the entry (one line), so a row that cannot fold is never silently unchecked; moves `checks_golden` only if a fixture case hits it (name it). **Option B**: leave as is (shipped data always folds). Small kit task either way; not queued by Build.
