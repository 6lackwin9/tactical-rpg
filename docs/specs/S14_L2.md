# S14-L2: CombatPresenter, tween presets, instant mode, animation lifecycle suite

Status: spec (design-brainstorm 2026-10-17; DECISIONS content-forge "S14 baseline answers": tweens on static tokens with an instant mode; approved by the user 2026-10-17)
Depends on: S14-L1 commit 2 (status icons for the status pop; the presenter works without them through `StatusArt` fallback)
Lane: logic only (no asset part)
Touches: new `scripts/ui/combat/combat_presenter.gd`, new `scripts/ui/combat/fx_presets.gd`, new `scripts/ui/combat/fx_settings.gd`, `scripts/ui/combat/combat_grid_panel.gd` (`_on_fx` and the move tween in `refresh` delegate), `scripts/ui/combat_grid_view.gd` (`animate_attacker_lunge`, `animate_token_impact`, `animate_token_pulse`, `animate_token_move`, `spawn_floating_combat_text` move into the presenter; the view keeps token lookup), new `scripts/tests/animation_lifecycle_test_suite.gd` + one line in `scripts/tests/suite_registry.gd`

## Goal

All combat animation goes through one presenter driven by the existing `CombatSession.fx_requested(entry: ActionLogEntry)` signal, with timings in one preset table, a speed setting and an instant mode that tests and headless runs always use. Every tween and temporary node is owned and cleaned up by the presenter. Logic never waits for animation (STRUCTURE conventions); nothing here changes resolution, the log or the sim.

## Schema contract (logic lane, schema first: no; presentation only)

### `FxSettings` (static, `RefCounted`)

| Field | Type | Default | Rule |
| --- | --- | --- | --- |
| `speed` | float | 1.0 | clamped 0.25..4.0; durations are divided by it |
| `instant` | bool | true when `DisplayServer.get_name() == "headless"`, else false | instant mode (rule 3) |

`FxSettings.load_from(cfg: ConfigFile)` reads `anim/speed` and `anim/instant` from the settings file owned by UI1-L (`user://settings.cfg`); until UI1-L lands nothing calls it and the defaults hold.

### `FxPresets.PRESETS` (const Dictionary, code table: presentation timing is not content)

Placeholder durations (seconds) are today's hard-coded values, so nothing looks different after the move.

| Preset id | Steps (tween recipe) | Durations |
| --- | --- | --- |
| `move` | slide token position to the target cell, quad ease-out | 0.25 (refresh slide 0.22 becomes this preset) |
| `attack_melee` | bump actor 30% toward the target, then back | 0.08 out, 0.12 back |
| `attack_ranged` | actor pulse (modulate flash, team accent colour) | 0.25 |
| `hit` | target shake x +4, -4, +2, 0 then white flash | 0.03, 0.03, 0.03, 0.04; flash 0.25 |
| `mitigated` | target shake as `hit`, flash steel `#94a3b8` | as `hit` |
| `heal` | target pulse green `#22c55e` | 0.3 |
| `buff` | target pulse gold `#eab308` | 0.3 |
| `defend` | actor pulse steel `#94a3b8` | 0.3 |
| `status` | status icon (StatusArt, 24 px) pops above the target, rises 16 px and fades | 0.55 |
| `float_text` | label rises (8, -28) cubic ease-out, scale to 1.0, alpha fades with 0.2 delay | 0.55, 0.25, 0.55 |
| `defeat` | target alpha to 0 | 0.4 |

Validation (assert in the suite, no runtime messages): every preset id used by `FxPresets.for_entry` exists; every duration > 0.

### `FxPresets.for_entry(entry: ActionLogEntry) -> Array[String]` (pure mapping)

| `entry.category` | Condition | Presets (in order) |
| --- | --- | --- |
| `MOVE` | - | `move` |
| `ATTACK` | grid distance `coord_from` to `coord_to` <= 1 | `attack_melee`, then `hit` or `mitigated` (`"MITIGAT" in outcome_tag`), `float_text` when `damage > 0` |
| `ATTACK` | distance > 1 | `attack_ranged`, then as above |
| `ATTACK` | `damage == 0` and `status_text` not empty | `attack_ranged` or `attack_melee`, `status` |
| `DEFEND` | - | `defend` |
| `BUFF` | `skill_subtype == "Support"` and `value_num > 0` | `heal`, `float_text` |
| `BUFF` | otherwise | `buff`, plus `status` when `status_text` not empty |
| `EVENT` | `"DEFEATED" in detail_text` or `outcome_tag == "DEFEATED"` | `defeat` |
| `TARGET`, other `EVENT` | - | none |

The builder checks the exact `outcome_tag` / `detail_text` values `CombatSession` writes today and keeps the mapping equal to the current `_on_fx` behaviour for the categories it already animates (the suite pins that equality).

## Rules (logic lane)

1. `CombatPresenter extends Node`, created by `CombatGridPanel` as a child. API: `play(entry: ActionLogEntry, actor: Control, target: Control, target_px: Vector2) -> void`, `slide(token: Control, to_px: Vector2) -> void`, `kill_all() -> void`, `live_count() -> int`, `temp_count() -> int`. `actor`/`target` may be null (that preset's step is skipped).
2. Ownership: every tween is created by the presenter (`create_tween()` on itself, bound to the token), stored in `_live`, and removed on `finished`; temporary nodes (labels, status icons) are added under the presenter's overlay layer, stored in `_temp` and freed (`queue_free`) by the tween's last callback. No other script calls `create_tween` for combat tokens.
3. Instant mode: `play` and `slide` apply each preset's end state synchronously (final position, modulate `Color.WHITE` or alpha 0 for `defeat`), create no tween and no temporary node, so `live_count() == 0` and `temp_count() == 0` right after the call.
4. Kill rule: `kill_all()` kills every live tween, sets each token to its end state, frees every temporary node immediately (`free()` on nodes not in the tree yet, `queue_free()` otherwise) and empties both lists. It runs on `session.log_reset`, `session.mounted`, `CombatSession.reset_round`/`step_prev` (through the panel's existing handlers) and the presenter's `_exit_tree`. No tween callback fires after `kill_all` (callbacks check a generation counter that `kill_all` bumps).
5. Overload: when `live_count()` exceeds `FxPresets.MAX_LIVE` (placeholder 24) at the start of `play`, the presenter calls `kill_all()` first, so a fast replay never lags behind the timeline.
6. Speed: every duration is `preset duration / FxSettings.speed`.
7. Sound hook: `play` emits `fx_played(preset_id: String, entry: ActionLogEntry)` once per preset; S14-L3 connects audio to it. No audio code here.

## Acceptance checks (rule-derived; `animation_lifecycle_test_suite.gd`, runs with the tree parent the test arena passes)

1. With `FxSettings.instant = true`, playing one entry of every mapping row leaves `live_count() == 0`, `temp_count() == 0`, tokens at their end states (position equals `target_px` for `move`, alpha 0 for `defeat`).
2. With `instant = false`: `play` of an ATTACK with damage creates live tweens and one label; after `kill_all()` both counts are 0 and the label is freed (`is_instance_valid` false after one frame); a callback counter stays unchanged for 0.6 s of awaited frames.
3. `FxPresets.for_entry` returns the table's list for one fixture entry per row; for the ATTACK, DEFEND, BUFF and MOVE fixtures of `combat_ui_framework_test_suite` (lines 86-89) the presets equal what the old `_on_fx` animated (lunge plus impact, pulse, pulse, move).
4. With `speed = 2.0` a `move` tween's total duration is 0.125 s (read from the tween's step).
5. Pushing `MAX_LIVE + 1` non-instant entries leaves at most `MAX_LIVE` live tweens.
6. `fx_played` fires once per preset in the mapping order.
7. The existing combat UI, dojo and session suites pass unchanged.

## Build notes (planner 2026-10-17)

Choices the build made where the code needed one; the suite pins each.

- Floating labels: DEFEND, Focus/other BUFF, MOVE `WITHDRAWN` and EVENT `AMBUSH` keep their pre-S14 `float_text` label (rule "equal to the current `_on_fx` behaviour"), so those rows end in `float_text`; the ATTACK label adds "DEFEATED!" when the target falls (one label instead of two).
- Grid distance: ATTACK entries carry no coordinates, so `for_entry(entry, distance := -1)` takes the distance from the presenter (actor and target token positions); unknown coordinates count as melee, the pre-S14 lunge.
- `status` preset: shown only when the entry names a real status (its outcome tag or status text equals a StatusRegistry display name); free text such as "Target HP: 30/50" or "Empowered" pops nothing (decision card in the build thread, recommended option).
- Target-side pulses (`heal`, `buff`, `status`, `defeat`) fall back to the actor when the entry has no target (Focus is self-only).
- Step back: the panel kills live FX when `(viewed_round, playhead)` goes backwards in `refresh`, which covers `step_prev`, rewinds and block inspection; `log_reset` (start, `reset_round`) and `mounted` call `kill_all` directly.
- Overload: `play` kills the backlog when the live count plus the tweens it is about to add would pass `MAX_LIVE` (each preset row has a `tweens` count), so the count never exceeds it.
- Suites run synchronously (no frames): tweens are advanced with `Tween.custom_step`, and "freed after one frame" is checked as queued for deletion.
- A new tween on a token first finishes that token's live tween on the same property; a refresh slide toward the end a live tween already heads to is skipped.
