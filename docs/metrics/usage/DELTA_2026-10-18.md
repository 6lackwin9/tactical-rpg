## Why cache reads stay high

- Every step a thread takes (each tool call and each wake) re-reads its whole context from cache. The fixed part alone (system prompt, tool list, CLAUDE.md, memory) is tens of thousands of tokens, so cache reads are ~95% of tokens in any agent setup; a 97-98% cache hit is the healthy case, not a leak.
- At API list prices a cache read costs about a tenth of fresh input and a 1-hour cache write about twice, so by cost the 07:57 mix is roughly: cache reads ~half, cache writes ~a third, output ~an eighth (estimate; plan usage limits may weigh tokens differently).
- What moves it: fewer steps per task (batched tool calls, gate output in files), fewer wakes on long-lived threads (relays, events, routines), and fewer idle gaps longer than the cache lifetime (each one re-writes the whole context: Balance 2.0M -> 6.5M cache writes overnight, 86-93% cache hit).

## What stands out

- A fresh session costs 4M to 13M in its first half hour (reading the handover and docs), so rotating more often has a floor cost.
- Platform's second session (20:29 to 07:50) used only 45M over 11 hours; its first session used 111M in under 5 hours. Long-lived but mostly idle threads are cheap; busy threads with big contexts are not.
- Balance grew the most overnight (+84.5M) with the most cache writes (6.5M): long sims leave it idle past the cache lifetime.
