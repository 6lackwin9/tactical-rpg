# C1: Orb and tome as off-hand weapon types, priest loses shields, caster gating

Archived 2026-10-17 (CLN-5), task done: kept for history; current rules live in docs/GAME_BRIEF.md and docs/decisions/. Do not build from this file.

Status: done (header was "proposed")
Depends on: slice A (done). B1 not required.
Lane: both. Logic part C1-L (schema first), asset part C1-A (split in two: C1-A1 needs nothing, C1-A2 needs C1-L).

## Goal

Orb and tome become real OFF-HAND weapon types (the user decided: every weapon is main 1H, main 2H or off-hand; orb and tome are off-hand only). `wpn_tome` is re-typed (today it is typed `orb` and sits in MAIN_HAND), `wpn_orb` is added, the priest loses shield proficiency, and caster skills that named `orb`/`tome` as a casting weapon now gate on a main-hand staff or wand. Orb = spell power plus reach, tome = support (heal power and debuff potency). The existing item schema cannot express those bonuses (`stat_bonuses` are STR..KNOW integers only), so C1-L adds a small item `effects` hook that reuses the passive effect grammar. No change to `DamageCalculator.compute`.

## Schema contract (logic lane, C1-L, schema-first: yes)

### Item validation (`ContentCatalog._item_errors`)

| Rule | Error when |
| --- | --- |
| Off-hand-only types | `weapon_type` is `orb` or `tome` and `slot` is not `OFF_HAND` |
| Category match | `weapon_type` is `orb` or `tome` and `off_hand_category` differs from `weapon_type` |
| Reverse match | `off_hand_category` is `orb` or `tome` and `weapon_type` differs from it |
| Never two-handed | `weapon_type` is `orb` or `tome` and `two_handed` is true |
| Weapon only | `weapon_type` is `orb` or `tome` and `item_type` is not WEAPON |

Unchanged: other `off_hand_category` values (`shortsword`, `knuckles`, `dagger`, `knife`, `shield`) and their rules; `Equipment.can_equip_in_slot` already sends off-hand-category weapons to OFF_HAND only, and `Equipment.hand()` already derives `off` for them (nothing stored).

### Hand rules (checks, no new code expected)

- A main_2h weapon leaves the off hand empty, so an orb or tome cannot be equipped with a staff (two-handed). The equip path must refuse it; if a code path allows it, fix it (report to the planner).
- With an orb or tome in the off hand the main hand must be a main_1h weapon or empty.
- The off-hand jab with an orb or tome uses that item's `base_power` (0 for both new items, see assets) plus stat scaling; it must not crash on power 0.
- Orb and tome `base_range` is 1, so they never make the wielder a ranged unit (verify `is_ranged_weapon` and the attack-range derivation read the main hand only).

### New field `effects` on equipment (items.json)

| Field | Type | Default | Applies to | Allowed |
| --- | --- | --- | --- | --- |
| effects | json list | `[]` | equip item types (weapon, shield, armor, accessory) | list of effect dicts below; empty allowed |

Effect types allowed on items: `skill_potency`, `status_potency`, `spell_reach`, `resist`. Anything else (`stat`, `proficiency`, `ap_regen`, `skill`) is rejected on items with "not allowed on items (use stat_bonuses / passives)". Passive validation keeps its current behaviour (a passive still needs at least one effect; add an `allow_empty` parameter to `Passives.validate_effects`).

| Effect | Fields | Validation | Meaning |
| --- | --- | --- | --- |
| `skill_potency` (extended) | exactly one of `family` (skill id) or `group` (`spell` or `heal`); `value` float | value non-zero, -0.9..2.0 as today; both or neither of family/group is an error | adds to potency like today; a `group` bonus applies to every skill in the group |
| `status_potency` (new) | `value` int | 1..25 | adds `value` points to the hit chance of every status the wielder inflicts with an ATTACK skill |
| `spell_reach` (new) | `value` int | 1..2 | adds `value` to the maximum reach of the wielder's spell skills (see rules) |
| `resist` | as passives | as passives | unchanged |

Group membership is DERIVED from the skill, no new skill field:

- `spell` = ATTACK skill whose `weapon_types` contains `staff` or `wand`.
- `heal` = SUPPORT skill with `heal_base > 0` or `heal_mult > 0`.

### Runtime hooks

- Item effects apply only while the item is equipped and are recomputed on every equip change (like `stat_bonuses`), never once-per-id like passives. Suggested: `Passives` keeps `apply`; add `Passives.apply_effects(c, effects, source)` shared by both and rebuild the gear-sourced bonuses from the equipment on change. Gear bonuses live in separate Combatant fields so they can be rebuilt: `gear_potency_group: Dictionary` (group to float), `gear_status_potency: int`, `gear_spell_reach: int`, plus the family bonuses that already feed `potency_bonus` (keep gear-sourced and passive-sourced separate so unequipping subtracts exactly).
- `Combatant.potency_for_skill(skill) -> float` = `potency_for(family)` + matching group bonuses; `SkillDef.power_for` and `SupportRules.heal_amount` switch from `potency_for(family_id())` to it. Default behaviour unchanged when no bonuses exist.
- `status_potency` is added where the attack command receives `status_potency` (plan entry), not in `StatusEffects.apply_chance`.
- `GearBudget.item_value` counts effects: `skill_potency` x 20.0 per 1.0 (so +0.10 = 2.0), `status_potency` x 0.2 per point, `spell_reach` x 3.0 per tile. Add the three weights as named constants next to the existing ones.

## Rules (logic lane)

1. Total gear `spell_reach` is clamped to 1 at runtime (two orbs are impossible anyway; this protects future items).
2. `spell_reach` raises `reach_max` by the bonus for a spell-group skill with `area` NONE, PLUS or BURST. For a skill with reach 0/0 (weapon default band) the band becomes (default min, default max + bonus) of the main-hand weapon. LINE and SWEEP are never extended.
3. A heal skill's amount is `heal_base + round(stat x heal_mult)` then multiplied by `potency_for_skill` (already the `SupportRules.heal_amount` flow); a `heal` group bonus of +0.10 gives x1.10.
4. A `spell` group bonus of +0.10 multiplies `power_for` by 1.10 for staff/wand skills; it does not change the weapon, so the Hit formula in `DamageCalculator.compute` is untouched.
5. Priest: `shield` is removed from the priest proficiency; nothing else in the class-rules validation changes. A priest-class unit with a shield override fails the existing "cannot equip" check.
6. Caster gating (assets, section below) uses the existing `weapon_types` mechanism; no code change. An orb or tome in the off hand never satisfies a skill's `weapon_types` (gating reads the main hand, which is already how `Combatant.can_use` works; verify with a test).

### Acceptance checks (rule-derived)

- Items: for every catalog item with `weapon_type` orb/tome the validator accepts exactly when slot, category, one-handed and WEAPON hold; one negative test per row of the validation table (use `validate_entry`).
- `Equipment.hand()` is `off` for `wpn_tome` and `wpn_orb`; a mage with a staff (main_2h) cannot equip `wpn_orb`; a mage with `wpn_wand` can, and the main hand is still the casting weapon.
- Effects: equipping `wpn_orb` raises `power_for(arcane_bolt)` by exactly x(1 + the orb's spell value) and an unequip returns it exactly; `wpn_tome` raises the mend heal by x(1 + heal value) and adds the tome's status points to a priest's `hex` chance; none of the three changes the damage of a non-spell skill (strike) or `DamageCalculator.compute` output for the same `skill_mult`.
- Spell reach: with the orb, the wand's default-band skill reaches max range + 1; `arc_lance` (LINE) is unchanged; clamp test with two synthetic orbs.
- GearBudget: `item_value` of the two new items equals the formula (derive in the test from the entry); mage and priest default loadouts stay inside the band (`GearBudget.check_class` clean).
- Proficiency: priest proficiency has no `shield`; priest `tome` level 3, `orb` level 2; mage `orb` 3 and `tome` 2 (unchanged).
- Tests that reference `wpn_tome` as an orb or a main-hand item (`foundation_test_suite.gd` HAND_TABLE keeps `wpn_tome: off`, Dojo loadout using `create_mystic_tome` at OFF_HAND) are updated by deriving from the entry.
