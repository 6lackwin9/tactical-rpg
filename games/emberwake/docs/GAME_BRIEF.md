# Game Brief (agent-facing: read this instead of crawling the codebase)

Tactical RPG on its own Rust engine, Aegis (`engine/`, since 2026-10-19), fully headless-testable: the rules live in library crates, the GUI only draws and sends command-API requests. The Godot 4.7 build it replaced is frozen in `legacy/` as an archive for reference.

How to read the rest of this brief: the rules, numbers and system notes below were written against the Godot build and still hold, because the engine ports them step for step under the same names (`DamageCalculator` -> `emberwake_rules::damage`, `CombatPlan` -> `emberwake_battle::plan::Plan`, `ContentCatalog` -> `emberwake_content::source` / `store`). A Godot class or `.gd` path below is found in the engine through the file table in `engine/docs/PORT_NOTES.md`; the Godot file itself is under `legacy/`. Godot-only tools named below (`ContentCatalog.upsert` seeds, `tools/fc.sh run`, scenes, suites in `scripts/tests/`) are replaced by `aegis content`, `aegis battle` / `aegis serve` and `engine/crates/*/tests/`.

## Core rules (numbers that tests depend on)

- Stats: STR DEX INT CONS PERC KNOW. Max HP = `roundi(60 * tier_mult) + CONS*8 + STR*2` for templated non-hero units (`max_hp_scaled`) and `roundi((60 + CONS*8 + STR*2) * tier_mult)` for other units (`tier_mult` from `tiers.json` `{id, mult, skill_cap}`: `hero 1.0, minion 0.4, standard 0.825, elite 1.25, boss 2.0`, `U1.2-S4`, `U2.3-TIERS`, `FB-145`; `tier_mult` is the only tier formula input since PR4-2, which removed the `tier_hp` / `tier_power` aliases). `Initiative = max(1, 8 + DEX - burden) - carry_overload` (floor 1; `carry_overload` applied in Dojo today, `U3.2-S5`); `Move Rate = clamp(floor((8 + DEX - excess + 2) / 5), 1, 4)` where `excess = max(0, burden - (7 + DEX))` lowers the move curve input by 5 pts/tile (`U1.2-S3c`). Crit = 5% + 1%/PERC above 10 (`CRIT_BASE`, `CRIT_PER_PERC`, `CRIT_PERC_FLOOR`; `U1.2-S3a`) + family `level2_bonus` (`crit` on weapons, `burden` on armour/shields; `U3.2-S4`), x1.5.
- Tier single scaling (`PR4-2`, kit `rpgkit_rules/src/derived.rs` on `aegis_core::formula::Formula::eval_marked`): on a templated non-hero, a derived formula never applies `tier_mult` to a stat again (a tier input sharing a `*` / `/` product with a base stat reads 1).
- Damage: `DamageCalculator.compute` (on `rpgkit_rules::pipeline`, `U1.2-S1` / `U4.2-S4` / `A2.2-S1..S2`) is the ONLY formula; `Unit::take_damage` delegates to `damage::take_damage(_traced)` on `pipeline::TAKE_GUARDED`, `Unit::heal` delegates to `damage::heal_gain(_traced)` on `pipeline::PASS` (capped at `max_hp` after the run), and `damage::compute_traced_folded` records the factors folded into `skill_mult` (`skill`, `exploit`, `flank`, `splash`, `counter`, `weaken`, `empower`) as trace-only parts. Attack Power = `((weapon power + training) x (1 - wield_penalty) + scaling stat x proficiency scaling (1.0-2.0, default 1.5)) x tier_mult` (for `Unit::tier_scaled` units whose stats are already scaled by `tier_mult`, `tier_mult` applies only to the weapon part and not the scaled stat part, `FB-144` / `FB-145`), floored at `MIN_POWER = 1` (`U1.2-S2`). Authored unit `power > 0` is absolute (`0` = derived). Hit = Attack x Focus x Skill x Stance matchup (1.25/0.75/1) x Crit x (1-Guard) x (1-Armor), armor = rating/(rating+50).
- Combat: 6 blocks per round, simultaneous resolution, AP pool with regen, skill AP = skill level, stances Offensive > Tactical > Defensive > Offensive, +1 AP stance switch, AP debt allowed.
- Classes (six shipped; seed scripts may add user classes): warrior (tank), ranger, priest (support), brawler, rogue, mage. `StatRules` / `unit_budget` (`U2.2-S1`, `U2.2-S3`): classes store float `base_shares` and `growth_shares` (`float_stats` schema field type; `base_stats` and `growth` are computed views on 62 and 5); class stats are `base_shares x 62 + growth_shares x 5 x (level - 1)`, rounded by largest remainder on the running total; unit spend pool = 4 + (level-1) spent exactly (or empty = `stats::auto_spend` following `growth_shares`), levels 1-10, skill tiers unlock by level (no skill cap; see "Skill unlock rule (SK2)" below), `tiers.json` rows (`{id, mult, skill_cap}`: `hero 1.0`, `minion 0.4`, `standard 0.825`, `elite 1.25`, `boss 2.0`, `U1.2-S4`, `FB-145`) scale `tier_mult`.
- Proficiency (`U3.2-S2..S4`, `C02-A`): `{gear type: {level 1-3, scaling 1.0-2.0}}` per class; any unit can equip any slot-fitting gear (`gear::trained_for`; `wears_untrained` retired in `U3.2-S3`, loader strips legacy keys). Untrained gear (Proficiency 0) takes a soft `0.75x` penalty on weapon base+tier power or armour mitigation plus `+1` burden; stat deficit past the requirement (discounted by `-2` per training level) ramps `15%`/pt up to `60%` on weapon power and armour mitigation (`Equipment::meets_requirements` / `wield_penalty`, shown as a red badge on the party screen). `UnitState::trains` and deck ownership read live passives via `progression::member_passives`. Family rows (`item_families.json`) define `engine_rules`, `level2_bonus` (live across all 21 trained families: `crit` `+2`/`+1` or `burden` `-1` at proficiency 2), and `level3_passive` (`grants::family_mastery`, 11 `mastery_*` passives at proficiency 3); worn item `skill` grants (`item_skills`, `OFFHAND1`) are active only while worn and need no path-level gate; skill `weapon_types` / `min_proficiency` gates stay hard.
- Passives (`U4.2-S1..S4`, `C02-A`): catalog templates (`modifier`, `proficiency`, `grant_skill`, `grant_pool`, `trigger` in `rpgkit_rules::grants`). Granted only by SOURCES: world character `temperament` (one slotless passive id on `characters.json`, plus optional `default_intent` and `ai_role`, `U4.2-S3`; seeded across the 13 party heroes in `C02-A`, applied in sim via `Runner::write` / `Runner::spawn_row`; loader maps legacy `passives[0]`), faction `grants`, discipline `passives`, named item `grants`, and family `level3_passive`. Never by classes/base units. All passive, gear, status, and meter band modifiers evaluate on `rpgkit_rules::pipeline` (`U4.2-S4`).
- Skills: class `skill_path` `{family: unlock level}` (order = entry position; `ClassArchetype.path_steps()` sorts by (level, position)) + `extra_skills` + `Combatant.learn_skill`. `Combatant.can_use` gates planner/AI.
- Units: class + level + side (party/enemy/neutral) + tier + spend + gear overrides, built through `rpgkit_rules::build_from(cat, UnitBuild)` (`U2.2-S2` / `U4.2-S2`, passives re-gathered live via `progression::member_passives`); `stat_mode: fixed` only for special units (`training_dummy` is a fixed warrior with no gear; a fixed unit with no class is a content error). Under `U2.3-TIERS` (`R4-1`, `aa311bf`, `858eaab`, `r41s2.json`), `rpgkit_rules::unit::template_for` picks a `unit_templates` row (`data/catalog/unit_templates.json`, keyed by `ai_role`: unit `ai_role`, else class's, or overridden by `units.template` `""` \| `"class"` \| role/id; `calcified_amalgam` and `inquisitorial_purifier` set `"template": "class"`) for any derived, non-party unit whose tier is not `hero` (`UnitTemplate::over` swaps `base_shares` and `growth_shares` while keeping the class's gear, skill path, basics, and loadout; templated core stats at level are `max(6, roundi(stat * tier_mult))` via `CharacterStats::scale_core` with gear modifiers unscaled, gear requirements (`Equipment::meets_requirements` / `wield_penalty`) and `KNOW` skill unlocks checked against unscaled stats, no double `tier_mult` on `scaling_stat` in `DamageCalculator`, and HP `roundi(60 * tier_mult) + CONS*8 + STR*2` via `max_hp_scaled` / `Unit::tier_scaled`). A goblin is lore on top of a minion class; worlds set level + explicit tuning deltas (`hp_pct, power, armor, speed, ap`).
- Worlds: base asset decides gameplay; two characters on one base unit behave identically except explicit tuning/items/passives.

## Known gameplay facts that surprise people

- Speed varies a lot by class (ranger ~35, warrior ~16 at level 5); never assume the warrior is faster.
- The planner resolves "friend vacates tile" fastest-first.
- Dojo warrior (Lv2, tank kit) hits the dummy for 47; dojo tests now derive this from the stats and weapon.

Stagger taken = stagger x windup (`stagger_windup_mult` `1.0` in `timeline` since `R1-BAL` `H6`, `2.0` default) x guard 0.5 x repeat 0.5 (broken last round) x flank 1.5 x passive (traced on `pipeline::STAGGER`, `U4.2-S4`). - Gear budget (M2d): `GearBudget` (`scripts/core/specs/gear_budget.gd`) gives each equipment item one weighted value (power 1.0, mitigation 1.5, stat bonus 2.0/pt, burden -2.0; `block_cost` and `W_EXTRA_BLOCK` retired in `U3.2-S1`) and sums a class's default loadout (pouch ignored) against TARGET_BUDGET 23 +-20%. ## Skill families and loadouts (M2c-2a1)

## Engine pieces (M2c-2a2)

- Cleanse: SUPPORT field `cleanse_statuses` (debuff ids or `all`) removes active AND pending debuffs via `SupportRules.apply` (never buffs; combinable with heal and `grant_status`). Planner options list what is removed and warn "Nothing to cleanse". Example `purify`.
- Disengage: `SkillDef.Kind.DISENGAGE` + `jump_tiles`; `CombatPlan._apply_disengage` picks the landing tile (farthest from the nearest/chosen foe, then shortest jump, nearest centre, lowest x/y; a GOTO step names the tile), `DisengageCommand` jumps (over units, not walls). It is the unit's move for the round (first, refused when rooted), AP = skill level. Example `backflip`.
- Plan claims (PLAN1): an ally's approach / go-to / landing tile is fixed once planned (`step.cell`; support approaches too) and a newly drafted ally avoids every friend's fixed tile (`CombatPlan.pinned_cell`); occupancy is evaluated fastest first, ties in planning order; `plan_apply_preset_all` redrafts any ally broken by a later draft. Enemy packs use the same claims and re-draft broken packmates the same way (`schedule_enemy_ai`, INTENT1-U follow-up).
- Area shapes and `affects` (`A3.2-S1`, `A3.2-K2`): `Area::{Plus, Burst, Line, Ring, Arc, Cone, Sweep}` (`RING`: 8 tiles around caster; `ARC`, `LINE`, `CONE`: drawn on the source tile along `skill::snap(source - from)`, where dominant axis snaps to cardinal and `|dx| == |dy|` keeps the exact diagonal, `IR7`; hazard `Shape::Arc` shares `skill::arc_cells`). Skill field `affects` (`""` | `all` | `enemies` | `allies`, `rpgkit_data::Affects`, `skill::affects_by`): explicit `affects` wins, else a skill that leaves a hazard hits `all`, `Assault` and `Stand` (`Guard`) hit `enemies`, `Support` hits `allies`, and `Field` / `Maneuver` / `classic` hit `all` (user never hit).
- Unarmed: `DamageCalculator` already uses STR+DEX with no weapon; `GearBudget.UNARMED_VALUE` (14) counts for an empty main hand.

## Skill unlock rule (SK2)

- A class path step `{level, skill}` owns a family. Tier t is castable at `unlock + unlock_offset` (offset default 0/2/4 for tiers 1/2/3). AP is only the per-round budget (no skill cap). Families of `grade` advanced or higher need path level >= 5; KNOW lowers an advanced family by `(KNOW-12)/4` and the passive `unlock` effect lowers any path family; the larger of the two applies, max 2 levels, advanced floor 3. Constants in `StatRules` (TIER_UNLOCK_STEP, ADVANCED_MIN_LEVEL, MAX_UNLOCK_REDUCTION, ADVANCED_UNLOCK_FLOOR, KNOW_UNLOCK_BASE/STEP, MAX_UNLOCK_OFFSET). Unlock levels freeze while the loadout is locked (battle). Read: `Combatant.family_unlock_level`, `tier_unlocked`.
