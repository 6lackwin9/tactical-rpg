# Project Aegis Engine

This directory contains the source code for the **Aegis Engine**, an agent-native game engine written in Rust that replaced the Godot build (frozen in `legacy/`, an archive; no build or test reads it).

**Current direction:** [docs/ENGINE_SPEC.md](docs/ENGINE_SPEC.md) (draft, 2026-10-18): headless deterministic sim, one command API shared by GUI and CLI, feel as data, engine goldens recorded on frozen fixtures (the Godot parity retired 2026-11-01). All engine work stays under `engine/`; `.gdignore` keeps Godot from scanning it.

### Vision & Trajectory: Agent-Native Spec-Driven Game Development

The core goal of moving from Godot to the custom **Aegis Engine** (`engine/` -> `kits/<genre>/` -> `games/<id>/`) is to establish an **agent-native, spec-driven game engine** where games are created, iterated on, and updated rapidly through written specs and interactive sessions with AI agents:

1. **Stage 1 — Engine & Kit Capability Foundation (`R1–R4`, complete):** Deterministic simulation core, rule contracts (`aegis rules --contract`), data-driven pipelines (`kits/rpg/schema.json`), and headless verification tools (`sim feel`, `audit-build`, `consistency-audit`, `scenario`) shipped through `R4` (`PR #58`).
2. **Stage 2 — Streamlined Game-Building Workflow (`Post-R4`, active):** Streamline the **end-to-end game-creation and update workflow**—turning specs and interactive human + agent design sessions directly into story content (`ACTS23` / `PK1`–`PK6`), polished player-facing UI (`ART_UI_STUDIO`), visual/scenario verification, and web deployment (`WEBREL1`, shipped in `PR #61`).
3. **Stage 3 — Multi-Genre Expansion (Future):** As new games and genres are explored beyond tactical RPGs, use the same spec + interactive agent workflow to author new genre kits (`kits/<genre>/`) and games (`games/<id>/`), using each new genre as an opportunity to organically expand the core `engine/` scope.

* **Game data:** the project's `games/emberwake/data/` folder (catalog, worlds, maps, quests, dialogue services, XP curve), read by the
  engine's own loader (`emberwake_content::source`) with the field tables in `kits/rpg/schema.json`; `data=<dir>` points the GUI or CLI at another data folder. * **Scenarios (INTEG1-E1, HEADLESS1):** `aegis scenario check|run|shots` walks real screens from `games/<id>/scenarios/<id>.json` (`engine/docs/authoring/scenarios.md`), `tools/fc.sh scenario`, with no window by default; `"window": true` in a file or `window=1` opens a real muted one; `aegis scenario shots <name>` takes proof shots with no file; `ui_tree` gains `frame`, `pid`, `px`; link `quit`; setting `start_inactive`; link sockets no-delay.
* **No window (HEADLESS1):** `aegis_ui::shell::headless`, launch arguments `headless=WxH [fps=] [dpr=] [idle_exit=]` (`Headless::from_args`, `Options::headless`): the same `Shell::frame`, screens and link, frames left in the software canvas; no `winit` window, GPU surface or sound device. 15 fps by default through `Pacer`, 12 to 240. Link `frames` (draw now; a screen's own `step` still reaches it) and `clip` (a numbered sequence). It exits when no link request has come for 120 s. `shell::save_png` refuses a blank or under-64 px frame, in a window too, and removes an older shot at the path; a refused F12 shows a notice. Bin `shot_compare <a.png> <b.png> [s=1]` over `aegis_ui::shot_diff`.
* **Window icon (ICON1):** a game's optional `game.json` `icon` names a PNG over the asset layers (`aegis content manifest`; a `.png` path inside the layers). `aegis_ui::icon` averages and sharpens it down when the window opens (`ICON_MAX` 256 px; on Windows a 32 px title-bar icon and a 64 px taskbar icon). No key means no icon; a missing or unreadable file is a start notice, never a crash. The `.exe` file's own icon is the game's: `emberwake_gui/build.rs` compiles `res/emberwake.rc` with the toolchain's `windres` (or `rc.exe` on MSVC, when on PATH) and links it, with no new crate; any other target or no resource compiler builds without an icon. `tools/game_icon.py` makes the `.ico` (16, 24, 32, 48, 64, 256 px; the whole crest down to 32, its arch at 24, the eye at 16).
* **Frame pacing (FPSCAP1):** `aegis_ui::pacing` (`pace`, `Pacer`, `FrameNeed`). The frame cap counts from the last frame, so a flood of events cannot break it. `Screen::frame_need` defaults to `Full`; a screen that opts out with `Within` or `Idle` rests until input, the agent link, its time or the 1 s heartbeat, and the most demanding need among the drawn screens wins. The link and a resize draw at once, past the cap.
* **Sprite fit (SPRITEFIT1):** a body's frame fills the asked size at any scale (`Image::fit_square`): plain nearest at an exact multiple, between multiples nearest at the next whole number and then `Image::reduce_box`, a true area average; below 1x `downsample`.
* **Fill fast paths (VISCLAR1-C):** `Painter::panel`, `Canvas::fill` and `image_alpha` fill by rows where every pixel is inside, with the same pixels; panels had taken 60-75 % of a frame. Test `tests/panel_fill.rs`.
* **Saves and settings:** per game under its id, `%APPDATA%/Aegis/emberwake/saves` and `%APPDATA%/Aegis/emberwake/settings.json` (outside the repo; the first start after SPLIT1-8 copies the old shared `%APPDATA%/Aegis/saves` and `settings.json` there and leaves them; `saves=<dir>` points the GUI elsewhere). The files use the engine's save format (saves below the current version are refused, CLN-47). The engine owns the sound, display and text-size settings (`aegis_ui::screen::Settings`) and applies them when they change (PORT-SETTINGS): window mode (windowed at the chosen size, borderless or exclusive fullscreen), vsync, frame-rate cap and text size (Small 0.85 to Extra large 1.3) and the four volumes and mute (PORT-AUDIO); the game adds its own keys.
* **Drag and drop (UIKIT2):** a screen marks a widget draggable with a payload key (`Ui::draggable("stash.3")`) and widgets as drop targets (`Ui::drop_target("slot.weapon")`); `Screen::can_drop` says which targets take a payload (outlined while dragging, gold under the cursor) and `Screen::accept_drop` acts on a release over one. A press on a draggable widget clicks on release when the mouse did not move; a move of more than 3 canvas pixels picks it up (a ghost card follows the cursor, `Ui::dragging` lets the screen preview); Esc, right click or a release elsewhere cancels.
* **Windows (UIKIT3):** a screen can keep a `window::Desk` of windows inside an area (returned from `Screen::desk`): each window has a title bar to drag it, a corner grip to resize it, collapse and close buttons, and a body the screen fills in `Desk::draw` (drawing and widgets clipped to it). A press on a window raises it, and a window covers what lies under it (clicks, hover, drops). `Desk::toolbar` draws a toggle per window and a button per layout preset; the shell handles all of these itself (widget ids `win.<id>.<part>`, `desk.toggle.<id>`, `desk.layout.<name>`) and saves the desk in the settings under `desks.<screen id>` after each change (`Desk::restore` reads it back). Geometry is stored as fractions of the area. Agent link: `windows` lists them, `window {id, op: open | close | raise | collapse | move | size, by: [dx, dy]}` or `window {layout}` drives them.
* **Held keys (STAGE1-O, WALK2):** `Cx::held` (`aegis_ui::Held`: shift, ctrl, alt, and `dir`, the step direction of a held arrow or WASD key; a screen whose `Screen::hold_walk()` is true walks on the held key, and the shell drops the OS key repeats for it) is the modifier keys held down right now; the shell keeps it current and clears it when the window loses focus, so a screen can show something only while a key is held (the battle outlines every unit while Alt is held).
* **Keyboard focus (PORT-FOCUS):** every screen's clickable widgets, choice fields and sliders take the focus with no
  code of their own (`aegis_ui::focus`, kept in the kit by the shell): Tab / Shift+Tab walk them in drawing order, the
  arrows move to the nearest one that way (a screen that walks or steers with the arrows says `Screen::arrow_focus`
  false: the region map, the journal), Enter or Space presses the focused one (a choice field opens its list and the
  arrows pick in it; Left / Right step a slider). A white ring shows the focus after a key moved it; a click hides it.
  `Screen::auto_focus` starts a keyboard menu focused (the main menu) on its first widget, or on
  `Screen::focus_first` when set. A question shows Yes then No, left to right, in both forms. A destructive question
  (`Cx::ask_no` / `ask_tag_no`, ASKNO1 and ASKNO2) opens with No focused, Enter = No and `y` = Yes, and through
  `Screen::pointer_to` asks the windowed shell to move the OS pointer onto No (only in a focused window, never for a
  screen an agent-link command opened, never in tests); `Cx::ask` / `ask_tag` keep Enter = Yes and open without a
  ring; the `ask` screen's state reports `default`. The agent link's `ui_tree` reports `focus` and
  `focus_visible`; `key` takes `backtab`; the link's `click` hides the ring like a mouse click. The focus starts over
  hidden on every new screen (a screen's own Enter / Space keep working); widgets under a popup or window take none;
  window title bars and toolbars take none yet, and a focused row is not scrolled into view.

* **Relative layout (LAYOUT720-E2):** `aegis_layout` resolves anchors, shares (per mille), fills and tokens to whole grid units for any area, by shared edges rather than sizes, so neighbours never gap and the parts add up to the room; a size that cannot fit becomes 0 and nothing panics. * **Window settings (DISPLAY2):** settings keys `fullscreen` and `borderless` replace `window_mode`, which carries over at load; `window_size` and Resolution are real pixels at any display scale, and a window keeps its pixels when moved to a monitor of another scale; a window is capped to the usable area (Windows `rcWork`, elsewhere the whole monitor), keeping its shape, the setting unchanged; a game passes its own size list through `Settings::keep_window_size`.
* **Ground composer (REGIONGROUND1-E1..E2, -L):** `aegis_ui::ground` names no ground: `compose(&GroundJob)` turns a cell grid and layers (`GroundLayer`: `order`, `tex` or flat `colour`, `wear`, `strays`, `tone`, `sunken`; `patches`, `marks`, `marks_per_100` and `PlacedPatch` draw over the composite: small random patches dropped whole near another ground or past `PATCH_CAP`, fainter as they grow; large ones only where placed; marks blend at 60 %. `patch_groups(job)` lists each candidate and whether it was kept. A job with `blocked` short of the grid, or past `PLACED_MAX` or `MARKS_MAX`, composes nothing) into one opaque image, `cell` art px per cell (`CELL_PX` 16, `TILTED_CELL` 16 x 12), a pure function of the job (no RNG state; noise is a hash of seed, field and lattice point, so the same bytes on every run). Textures are sampled by art pixel with a map-wide tone of no period; grounds meet at a blurred cell mask pushed by shared noise and thresholded, with a worn band, strays and bites (at most 6 art px from the cell boundary, hard at art pixels, no blending). Limits: `CELL_MAX` 32 art px per cell, `LAYERS_MAX` 255, `ART_PX_MAX` 16 million; past them a job composes a 0 x 0 image. A texture's offset comes from its layer's place in the list, so keep the game's order (`order` alone sets paint order). `draw(p, key, r, job)` caches: 4 art images by `GroundKey::of(map, job)` (map id, a hash of the cells, numbers and every texture pixel, cell size; make it when the job changes and keep it, never each frame), 1 physical copy per thread at the window's size, blitted inside the clip (two sizes in one frame re-copy each frame); a resize or view flip makes one new copy, a map edit one compose, a copy past `PHYSICAL_MAX` (64 MB) draws through `Painter::image`. `ground_composes()`, `ground_expands()`, `ground_held_bytes()` read it. `soft_ellipse(rx, ry, col, alpha)`: a soft shadow blob. Tools: `cargo run -q -p aegis_ui --bin ground_compose -- JOB.json OUT.png` (`ground::compose_file`; the job's fields there, a bad number refused rather than cut), `-- --timing` in release prints compose, copy and blit for a 48 x 30, 8-layer job. Gallery: the Tiles page's Ground switch. The region map draws it through `emberwake_gui/src/ground.rs` (REGIONGROUND1-L); `Art::generation` differs for every `Art`, so something kept from its pictures can tell a new one. Spec `docs/specs/REGIONGROUND1_ENGINE.md`; tests `aegis_ui/tests/ground.rs`, pinned pixels in `tests/fixtures/ground/` (`AEGIS_GROUND_WRITE_PINS=1` rewrites them, only after tuning on purpose).

The UI Gallery's Kit widgets entry has a Theme page (roles, contrast pairs, faces, the header, badge and inset pieces, every frame role, and an engine default / layers' theme / frames off switch that resets when the page or the gallery is left). Tests `aegis_ui/tests/theme.rs` (pixel identity against frame hashes recorded before E1). A frame sidecar's `reduce: average` (LOOK1-R1) averages a high-resolution frame to the window when `scale` exceeds the view's scale, cached per frame, size and view scale in `Painter::nine` (at most 8); other frames sample as before. `straddle` centres the frame on the panel's boundary (the rect, layout and hit area stay; the overhang only draws, under the clip), `corner_anchor` names the art px on the panel's corner point, the corners follow the window at `scale` and keep one size on any panel, as large as fits on a panel too small for two, `edges: tile` repeats a straddled edge at its art's size, and `sharpen` masks the reduced corners. `painter::nine_content_rect` gives a screen the content rect past the corners at the size they draw. * **Pip gauge (INPUT1-AP, style D since INPUT2):** `aegis_ui::pips::PipGauge` draws a budget planned against on fixed

## Driving a battle from the CLI (agents)

`aegis serve` reads one JSON request per line and answers one JSON line each (full list in
`../kits/rpg/crates/rpgkit_host/src/lib.rs`, KIT1-N):

```bash
printf '%s\n' '{"cmd":"new","encounter":"goblin_skirmish"}' \
  '{"cmd":"plan","unit":"Warrior","steps":[{"mode":"engage","skill":"strike","target":"Goblin Brawler"}]}' \
  '{"cmd":"preset","unit":"Ranger","preset":"focus_weakest"}' '{"cmd":"resolve"}' | aegis serve
```

Every mutating request is recorded; `{"cmd":"history"}` returns them (and the checkpoints: the round outcome after
every concluded round), and feeding them to a fresh `serve` replays the battle exactly.

`new` also takes `ruleset` (`classic` or `timeline`; default classic for a catalog encounter, the world's for a world
encounter) and `rules` (`"-id,+id"`, extensions only; RULESET1-R); the CLI takes the same as
`aegis battle <encounter> ruleset=<id> rules=<-id,+id>` and the sim as `ruleset=` / `rules=`.
The battle state always carries `ruleset` `{id, melee_diagonal}` (CLN-46; it was only beyond classic before).
`new` also takes `plan_reveal`; under the rule `plan_badges` the `intents` reply gains `round_intents` (both sides: intent, target, Maneuver kind, impact badges, tell, plan) and `intel {unit}` gives one unit's record (RULESET1-V).

## Playtest recordings and replay (PORT-PLAYTEST)

While recording is on (the setting `record_playtests`, on in debug builds), the GUI keeps one recording per run in
`%APPDATA%/Aegis/<game>/playtests/<id>.json`: every arena battle's command-host session (its requests from `new`
and the checkpoints), saved when the battle ends, restarts or the screen closes, with the content fingerprint of the
data folder (`aegis_host::playtest`, the hub `aegis_ui::playtest`), and the UI trail: clicks (the widget, handled or
not), widget presses, keys, hovers of 700 ms or more, screen changes, overlays as modals, plan edits, confirms, the
battle's end, errors and panics, and missing art (`aegis_host::trail` reads it). Party battles of the world map
start outside `new`, so their replay waits for PLAYTEST2.

F5, F6, F7, F9, F10 and F11 reach the top screen as `Key::Fn(n)` for its debug use (agent link keys `f5`, `f6`, `f7`, `f9`, `f10`, `f11`; a screen that does not use one ignores it; repeats of all but F7 are dropped); F8 and F12 stay the shell's.

F8 (recording on) takes a note: the screen as it was goes to `<id>/note_<n>.jpg`, and a box asks for the text (types
at once) and tags (mechanic, ui, ux, bug); Ctrl+Enter saves, Esc cancels. The note stamps the screen, mouse, control
and the battle's round, block and phase. The kit's text field (`Ui::text_field`, single or multi-line) edits through
the shell (`Kit.edit`, `Screen::text_changed`) with a full editor (PLAYUI1-T, `aegis_ui::edit`, re-exported from `ui`):
it wraps at spaces and scrolls (`<id>.scroll`); Up/Down by visual line (sticky column), Home/End, Ctrl+Home/End,
Page Up/Down, Ctrl+Left/Right, Ctrl+Backspace/Delete, Shift selects, mouse drag, Shift+click, double click selects a
word, Ctrl+A/C/X/V, Ctrl+Z/Y; undo groups a typing run (a 1 s pause, a move or a delete ends it; 100 steps); the
clipboard goes through `arboard` with an in-app fallback. The F8 note box is a full-height text area. The kit also has
an icon button (`Ui::icon_button`: an image from the asset layers or a drawn `Glyph`, hover card, focus, toggled and
disabled states) and a collapsible section header (`Ui::section`) (PLAYUI1-K).

The Scene Runner's **Playtests** (`aegis_ui::recordings`, a kit screen the game opens with its own launcher) toggles
recording and lists the user folder's recordings and the game's repo folders (`playtests/inbox`, `playtests/repro`,
badge `repo`) with a stale badge: per battle Play back (watch it to its end, not recorded) or Take over at a round
(replayed, then played on as a new session whose `end.parent` names the recording, battle and request), the notes
(click a note's row, `recordings.note.<i>`, to read it whole in `recordings.note_view` with Copy), Open folder and Copy to repo (the recording and its images into `playtests/inbox/<id>/`).

```bash
aegis replay <recording.json>                       # every battle: each checkpoint match / diverge (path, values) / unverified
aegis replay <file> battle=0 until=12 json          # stop after 12 requests (what a take-over replays), JSON report
aegis replay <file> variant=patch.json write=out/   # {"at", "remove", "requests", "then": "stop"|"recorded"}: DIFF lines, saved run
aegis replay <file> seeds=1..50 fallback='{"cmd":"autoplay","preset":"balanced"}'   # results under other seeds
aegis replay <file> trail-report                    # the UI trail's flags: dead or repeated clicks, long hovers, errors, panels
```

Exit 0 when everything matches (changed data files only warn: "content stale"), 1 on a divergence or a refused
request, 2 when the recording does not load. `tools/fc.sh replay ...` is the same.

## The game (emberwake)

```bash
cargo run --release -p emberwake_gui                       # the main menu; screen=runner (dev tools) or screen=arena
cargo run --release -p emberwake_gui -- screen=arena encounter=goblin_ambush seed=3
```

The main menu leads to New game (world cards), Continue / Load, Settings and Tools (the Scene Runner: Combat Arena on
any catalog or world encounter (World / Classic / Timeline rules, single extensions switched, "Reveal enemy plans", a
ruleset chip: RULESET1-G), Content Forge, World Forge, Gear & Skill Dojo, Exploration (a world from any location or its world map,
nothing saved, a fight skipped as a win at no cost or fought), and the UI Gallery: the kit's widgets, every screen and the battle's panels one at a time). In play: arrows / W A S D walk, E interacts with the marker you face, a click walks there
(or uses a marker), Esc opens the game menu (party, journal, save, load, settings, quit). Both maps have a HUD bar
(PLAYUI1-H): the place name top left; gold, supplies and icon buttons top right (P party, J journal, I stash = the
Character popup's Gear tab, ? help, Menu), off while a conversation, shop, turn-in or lore page is open. Talking opens the dialogue box at the bottom centre with the camera on both speakers (1-9 choose); shops, turn-ins and lore open as popups; a world-map exit opens the world map (click a node, Travel,
Make camp, Enter). Fights open the battle screen with the saved party; Continue settles the outcome and shows the
results. The screen list and what is left: [games/emberwake/docs/SCREENS.md](../games/emberwake/docs/SCREENS.md).

In battle: hover anything (units, cards, plan blocks, menu options) for a detail card. Click a hero to select it; click
a foe, an ally, the hero itself or an empty tile for its options (each shows AP and the expected damage or heal); right
click closes a menu or undoes the last step. Strip: the Party and Hero dropdowns draft a tactic (with its
description), Auto plays the battle out, Confirm resolves the round. The log (Expand) wraps and scrolls with the wheel
or PageUp / PageDown. Keys (while no control shows the focus ring): Enter confirm, Space step / next round (timeline battles: nothing while planning, Enter is ignored for 350 ms after an advance, and the next round's planning comes by itself: Settings, Gameplay, "Auto-confirm next round", on by default; classic keeps its Next round), A autoplay, Z undo, L log, R restart (arena),
I enemy tells, F12 screenshot. Timeline battles (INPUT1-U): click a target (an enemy, an ally, an empty tile; the hero
panel's Self button or S for the hero itself), then pick skills from its menu (Shift+1-9 are the selected hero's skill
hotkeys, with or without the menu open; INPUT2); keys 1-4 select the party's members; the planner fills the rest of
the round as ghost blocks (Settings, Gameplay: "Auto-fill the rest"); F accepts the selected hero's ghost as picks and
a click on a ghost block accepts it up to there; while a hero shows only its ghost, a click on another ally selects it
and Ctrl+click opens the hero's support menu on it; Z or a right click undoes the last pick, Clear removes them all; a right click or a click outside
closes the menu. Selection and inspect (INPUT1-U slice 3): a right click on any unit (token or card) inspects it, pinning
the threat intel panel ("Inspecting `<name>` (Esc clears)") until another inspect, Esc or the next round, with only what
the party knows (an enemy's unrevealed plan never shows); a click on the selected hero (token or card) selects nothing;
with no hero selected, or outside planning, a click on an enemy inspects it and one on an ally selects it; Esc closes
the menu, then the log, then clears the inspect, then selects nothing, then (Arena) leaves. Full timeline view
(INPUT1-T, a battle beyond classic): T opens every unit's track over the grid panel (the party's plans with their
ghosts, an unrevealed enemy masked with its intent, target and tell, during playback only its started actions); T or
Esc (before the steps above) closes it; a click on a party track selects that hero. Playback aids (INPUT1-PB, a
battle beyond classic): each impact draws a short tracer from its actor to what it hit, the strip frames the resolving
block, P cycles the playback speed (1x, 0.5x, block by block; also Settings, Battle) and N plays the next block, the
expanded log groups its lines by round and block, and T during playback pauses at the end of the resolving block until
the view closes.

Feel values (timings, floating numbers, hit flash, colours) live in `games/emberwake/tuning.json` and reload while the game
runs. The GUI serves an agent link on `127.0.0.1:47800`: `ui_tree` (the screen stack, the music wanted, the top screen's state and every
widget with its id, text, rect, state, hover card and drag or drop key), `click {id}` (a select opens its list and replies with the option ids, `<id>.opt.<n>`), `drag {id, to}` (press, move, release to `[x, y]` or onto a widget id: slider drags and drag and drop), `hover {id}`, `type {text}` (into the text field being edited), `note` (F8), `key {key}` (up / down / left /
right / enter / space / esc / a letter; while a field edits also home, end, backspace, delete, `shift+...` and
`ctrl+a/c/x/v/z/y`, and enter, esc and tab end the edit; `ui_tree` then reports `edit` {id, caret, selection, selected,
undo}), `back`, `screenshot {path, max_w}`, `text_audit {scale, shot}` (TEXTFIT1: one
frame of the top screen at a text size, the mouse off the canvas, reporting the text `text_fit` or a button shortened
(cut), text past the canvas (edge), texts drawn over each other (overlap) and text running out of its control (spill);
text in a scroll area or under a later panel is skipped, and so is transient text drawn inside `Painter::transient`
(TEXTFIT2: floats that rise and fade, such as damage numbers; the painter flag `Fonts::transient` marks the record
`TextRec::transient`); `shot` saves that frame), `game` (the full game state), and the
battle command API while a battle is open. An agent sees and does exactly what the player sees and does:

```bash
aegis link '{"cmd":"ui_tree"}' '{"cmd":"click","id":"menu.new_game"}' '{"cmd":"click","id":"new_game.start"}' '{"cmd":"key","key":"right"}'
```
